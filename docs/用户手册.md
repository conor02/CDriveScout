## 一、安装与启动

### 1.1 它是绿色软件

不需要安装程序，也没有注册表写入。整个程序就是一个文件夹：

```
CDriveScout\
├── CDriveScout.exe          ← 双击这个
├── rules.ini                ← 分类规则，必须和 exe 放在一起
├── resources\app.asar       ← 程序本体
└── （一堆 dll / pak 文件）   ← Electron 运行时，别删
```

> ⚠️ **必须整个文件夹一起拷贝**。Electron 程序不是一个 exe 就能跑，单独拿走 `CDriveScout.exe` 会打不开。

### 1.2 第一次启动

双击 `CDriveScout.exe`。如果 Windows 弹出「已保护你的电脑」（SmartScreen），点 **更多信息 → 仍要运行**。
原因是没有代码签名证书，不是文件有问题；源码全部在这个仓库里，可以自己审计或自己编译。

程序不需要管理员权限。想清理 `C:\Windows` 或 `C:\Program Files` 下的文件时才需要提权，而这类文件本来也属于「系统保护区」，不建议动。

### 1.3 卸载

直接删掉整个文件夹即可。程序不写注册表，唯一的外部痕迹是 Windows 回收站里你自己移进去的文件。

### 1.4 升级

用新版本的整个文件夹替换旧的。**注意保留你改过的 `rules.ini`**，否则自定义规则会丢。

## 二、界面总览

```
┌─────────────┬──────────────────────────────────────────────────────┐
│ 扫描盘符     │  可安全清理 │ 建议迁移 │ 需确认 │ 系统保护区 │ 其他  │
│ 体积门槛     ├──────────────────────────────────────────────────────┤
│ 开始扫描     │  文件排行 │ 目录占用                  显示 N 条     │
│ 分类筛选     ├──────────────────────────────────────────────────────┤
│ 搜索         │  ☑ │ 大小 │ 分类 │ 建议 │ 路径 │ 修改时间          │
│ 导出         │    （勾选后，这里浮出操作条）                          │
│ 操作按钮     │                                                      │
└─────────────┴──────────────────────────────────────────────────────┘
```

### 左侧栏

| 控件 | 作用 | 建议 |
|---|---|---|
| **扫描盘符** | 选要分析的磁盘，下拉里带剩余空间 | 默认 C 盘 |
| **只列出大于** | 体积门槛：全部 / 1 / 5 / 10 / 50 / 100 MB | 默认 5 MB；想查「谁在吃盘」够用，想看全部细节调成 1 MB |
| **跳过系统目录** | 扫描时不进 `C:\Windows`、`Program Files` 等 | 只想找用户文件时勾上，快 2–3 倍 |
| **列表中隐藏「系统保护区」文件** | 只影响显示，不影响统计 | 默认勾选，符合「除系统外」的直觉 |
| **按分类筛选** | 六个胶囊按钮，点一下只看这一类 | 与 KPI 卡联动 |
| **搜索路径** | 按路径关键字过滤，不区分大小写 | 输入 `微信` 只看微信相关；输入 `node_modules` 找开发缓存 |
| **导出 CSV / HTML** | 导出**当前筛选结果**，不是全量 | 见第七章 |
| **打开规则文件 / 重新加载规则** | 编辑 `rules.ini` 后即时生效 | 见第八章 |

### 右侧主区

- **KPI 卡**：五类的体积与文件数，点一下即筛选，再点一下取消
- **文件排行**：一个文件一行，虚拟滚动（10 万行也不卡）
- **目录占用**：按目录聚合，看「哪个文件夹最占地方」
- **状态栏**：左边是进度/结果，右边是保留条数与跳过数量

## 三、扫描

### 3.1 三种典型配置

| 目的 | 盘符 | 体积门槛 | 跳过系统目录 | 隐藏系统保护区 |
|---|---|---|---|---|
| 找「谁在吃 C 盘」 | C: | 5 MB | 否 | 是 |
| 只想清用户区缓存 | C: | 1 MB | **是** | 是 |
| 查系统文件占用 | C: | 10 MB | 否 | **否** |

### 3.2 扫描过程

点「开始扫描」后：

- 状态栏实时显示已读文件数、累计体积、耗时、当前目录
- 已有结果会边扫边出现，不会等全部扫完才显示
- 「停止」按钮会中断扫描，**已扫到的结果保留**，可以继续筛选和操作

整盘扫描的实测速度：约 42 万文件 / 80 GB，冷缓存 10.8 秒，热缓存 6 秒左右。
速度取决于磁盘类型和文件数量，机械硬盘会明显更慢。

### 3.3 扫不到东西怎么办

| 现象 | 原因 | 处理 |
|---|---|---|
| 一条都没有 | 体积门槛太高（比如选了 100 MB） | 调低门槛重扫 |
| 结果远少于预期 | 勾了「跳过系统目录」 | 取消勾选重扫 |
| 某个目录完全没出现 | 无权访问（如其他用户的目录） | 用管理员身份运行，但通常没必要 |
| 总量比资源管理器少几 GB | 分页/休眠/还原点被跳过 | 正常，见 [4.5](#45-为什么总量比资源管理器少) |

## 四、看懂结果

### 4.1 五档分类

| 分类 | 判断依据 | 典型文件 | 建议 |
|---|---|---|---|
| **可安全清理** | 命中缓存/临时/日志类规则 | `\Temp\`、`\Cache\`、`*.tmp`、`*.dmp`、`npm-cache` | 删除，程序会自己重建 |
| **建议迁移** | 是用户数据但不必放 C 盘 | 下载、桌面大文件、视频图片、微信/QQ 文件、Steam 库、ISO | 迁到 D 盘 |
| **需确认** | 有价值但取决于你 | 压缩包、安装包、`*.vhdx`、`*.mp4`、exe | 自己看 |
| **系统保护区** | 位于 Windows / Program Files / ProgramData 等 | `WinSxS`、驱动、系统组件 | 不要动 |
| **其他** | 没命中任何规则 | 文档、代码、普通软件数据 | 自行判断 |

**「判断依据」这一列**会告诉你它是被哪条规则命中的，比如「应用缓存目录，删除后自动重建」。看不懂就去 `rules.ini` 里搜这一句。

### 4.2 红色「系统」角标

有些文件**位于系统目录，但确实可以清**，比如 `C:\Windows\Temp\*`。
这类文件会保留「可安全清理」的分类，同时额外标一个红色「系统」角标，提醒你它在系统目录里。

默认只有「可安全清理」能穿透系统目录，其余分类在系统目录里一律降级为「系统保护区」。

### 4.3 排序与筛选

- 点表头切换排序：大小 / 分类 / 建议 / 路径 / 修改时间，再点一次反向
- 默认按体积降序 —— 找占空间的东西，这是最有用的顺序
- 分类胶囊、KPI 卡、搜索框三者**同时生效**（交集）

### 4.4 目录占用页

把当前筛选结果按目录聚合，显示 Top 120。聚合粒度：

- `C:\Users\<用户名>\` 下取 5 层（能拆到 `AppData\Local\Google\Chrome\User Data`）
- 其他路径取 4 层

百分比口径是**占当前筛选结果的总和**，不是占全盘。所以筛了「可安全清理」之后，占比是这一类内部的占比。

### 4.5 为什么总量比资源管理器少

以下内容被系统独占或刻意跳过，不计入统计：

- `pagefile.sys`（分页文件）、`hiberfil.sys`（休眠文件）
- 系统还原点、`System Volume Information`
- 回收站 `$Recycle.Bin`
- 无权限访问的目录（状态栏右下角会显示「跳过/无权访问 N 处」）

这是刻意的设计：**宁可少报，也不去猜**。这些项也不该由第三方工具动。

### 4.6 右键菜单

在任意一行上右键：

| 项 | 作用 |
|---|---|
| 在资源管理器中显示 | 打开所在文件夹并选中该文件 |
| 复制完整路径 | 复制到剪贴板，方便贴到别处查 |
| 移到回收站… | 只对这一个文件走完整确认流程 |
| 迁移到其他盘… | 同上 |

## 五、移到回收站

### 5.1 完整流程

1. **勾选**：行首复选框，或用表头复选框全选当前筛选结果（受保护目录会自动跳过）
2. 勾选后主区顶部浮出操作条，显示「已选 N 项 · 总体积」
3. 点 **移到回收站**
4. **第一步：清单预览** —— 逐个列出要移走的文件、大小、合计
5. 点「继续 →」
6. **第二步：最终确认** —— 必须勾选「我已核对上面的清单」，按钮才可点
7. 点「确认移到回收站」开始执行，弹窗显示进度

### 5.2 三道保险

| 保险 | 表现 |
|---|---|
| 受保护目录不可勾选 | 复选框直接禁用，鼠标悬停提示「系统保护区或受保护目录，不可操作」 |
| 执行前复核 | 主进程会再逐项检查一次，被篡改的请求直接拒绝 |
| 超量二次输入 | 单次超过 200 项或 5 GB，还要手动输入「确认」两个字 |

### 5.3 上限与分批

- 单次最多 **800 个文件**，超过会提示分批操作
- 清单预览最多显示前 200 行，但**实际处理的是全部**，底部会显示真实总数与总体积

### 5.4 怎么还原

打开 Windows 回收站，找到文件 → 右键 → **还原**，会回到原路径。

> 💡 回收站里的文件**仍然占用磁盘空间**，要真正腾出空间必须清空回收站。所以「移到回收站」的确切含义是「先挪开，确认没问题再清空」，不是立即释放。

## 六、迁移到其他盘

### 6.1 完整流程

1. 勾选要迁移的文件（可以跨目录、跨分类多选）
2. 点 **迁移到…**
3. 填目标目录：
   - 手输，如 `D:\Moved`
   - 或从「选盘符…」下拉里选一个盘，自动补成 `D:\CDriveScout-Moved`
   - 或点「选择…」弹目录选择框
4. 决定是否**保持目录结构**（默认勾选，强烈建议保留）
5. 选校验方式
6. 看下方的空间提示：`D: 剩余 483 GB · 本次约需 1.86 GB · 空间充足`
7. 点「生成预览 →」→ 看到「源 → 目标」的映射清单 → 继续 → 最终确认 → 执行

### 6.2 目录结构：保留还是打平

| 选择 | 结果 | 风险 |
|---|---|---|
| **保留结构**（默认） | `C:\Users\Alex\Downloads\a.iso` → `D:\Moved\C\Users\Alex\Downloads\a.iso` | 无，路径唯一 |
| 不保留 | → `D:\Moved\a.iso` | 不同目录的同名文件会互相冲突，冲突时自动加 ` (2)` 后缀 |

选「保留结构」时，目标盘的目录会长成 `D:\Moved\C\Users\...` 这样 —— 看着有点长，但它保证了你随时能看出文件原本在哪。

### 6.3 校验方式

| 方式 | 规则 | 适用 |
|---|---|---|
| **智能**（默认） | ≤ 2 GB 的文件做 SHA-256 逐字节校验；更大的只比大小 | 绝大多数场景 |
| 快速 | 只比对文件大小 | 文件很多、或信任源盘时更快 |

SHA-256 校验意味着**读两遍文件**（源一遍、副本一遍），速度大约是纯复制的 1/3。大文件多时想快就选「快速」。

### 6.4 执行链与失败处理

```
复制副本 → 比对大小 → （可选）比对 SHA-256 → 保留修改时间 → 原件进回收站
```

任何一步失败都**不会丢文件**：

| 失败点 | 处理 |
|---|---|
| 复制出错（磁盘满、权限、被占用） | 删掉本次写坏的副本，原件保留 |
| 大小或哈希不一致 | 删掉副本，原件保留，结果里标红 |
| 目标已存在同名文件 | 放弃该文件，**不覆盖、不删目标** |
| 原件移入回收站失败 | 副本保留（已校验），结果里标记「已复制，但原件未移入回收站」 |
| 中途点取消 | 当前文件中断，已完成的仍然有效，半成品副本清理掉 |

执行完会弹结果汇总：成功多少项、失败哪些、失败原因。失败的项可以单独重试（重新勾选再执行一次即可，已存在的目标文件会被跳过）。

### 6.5 迁移之后要做的

迁移**不会**自动修改任何软件的配置。这些需要你自己处理：

| 类型 | 建议做法 |
|---|---|
| 微信 / QQ 文件 | 优先用软件自带「更改存储路径」功能，比迁移后手动改配置更稳 |
| Steam / Epic 游戏 | 用启动器自带的「移动安装文件夹」 |
| 开发缓存（npm/pip/gradle） | 改环境变量（如 `npm config set cache`），再删旧目录 |
| 普通文档/视频 | 直接迁移即可，但快捷方式会失效 |
| WSL / Docker 虚拟磁盘 | 用官方 `wsl --export/--import`、Docker Desktop 设置，**不要**手工迁移 `ext4.vhdx` |

> ⚠️ 规则文件里对这些情况都写了对应提示，看到「先用官方方式迁移」就照做。

## 八、自定义分类规则

规则文件是 exe 同级的 `rules.ini`，纯文本 UTF-8。改完保存，点界面上的「**重新加载规则**」立即生效，**不用重启，不用重新打包**。

### 8.1 三个段落

```ini
[system]     # 系统保护区：前缀匹配
[protect]    # 保护名单：界面不可勾选，执行前再拦一次
[rules]      # 分类规则：自上而下，第一条命中即生效
```

### 8.2 规则语法

每行一条，用 `|` 分隔 5～6 段：

```
分类 | 匹配方式 | 模式 | 建议动作 | 判断依据 | [sys]
```

| 字段 | 可选值 |
|---|---|
| 分类 | `可安全清理` / `建议迁移` / `需确认`（系统保护区与其他由程序自动判定） |
| 匹配方式 | `contains` / `prefix` / `ext` / `name` |
| 模式 | 路径片段、前缀、扩展名或文件名 |
| 建议动作 | `删除` / `迁移` / `需确认`，会显示在「建议」列 |
| 判断依据 | 显示在界面上的一句话，给人看的 |
| `sys`（可选） | 写了表示「即使在系统目录内也保留这条规则」 |

### 8.3 四种匹配方式

| 方式 | 第三段写法 | 完整规则示例 | 命中示例 | 注意 |
|---|---|---|---|---|
| `contains` | `\cache\` | `可安全清理\|contains\|\cache\|删除\|应用缓存` | `C:\App\Cache\x.dat` | **建议以 `\` 收尾**，否则 `cached` 也会命中 |
| `prefix` | `D:\Games` | `建议迁移\|prefix\|D:\Games\|迁移\|游戏库` | `D:\Games\...` | 用于整棵目录树 |
| `ext` | `.iso` | `建议迁移\|ext\|.iso\|迁移\|镜像文件` | `a.iso` | 只比扩展名，记得带点 |
| `name` | `thumbs.db` | `可安全清理\|name\|thumbs.db\|删除\|缩略图缓存` | `Thumbs.db` | 文件名完全相同，不区分大小写 |

> 注意：模式里的反斜杠是**字面字符**，不需要转义。`\temp\` 就是匹配路径里出现 `\temp\`。

### 8.4 顺序很重要

规则自上而下匹配，**第一条命中即生效**。所以特殊规则必须写在通用规则前面。

例子：你想让 `C:\Users\Alex\Downloads\Important\` 里的东西不算「建议迁移」：

```ini
# 先写特例
需确认|contains|\downloads\important\|需确认|这个目录里的东西不能自动清
# 再写通用规则
建议迁移|contains|\downloads\|迁移|下载目录，建议整体迁到 D 盘
```

反过来写就永远不生效。

### 8.5 常见改法

**新增一个软件的缓存目录**

```ini
可安全清理|contains|\appdata\local\yoursoft\cache\|删除|YourSoft 缓存，删除后自动重建
```

**把某个大目录列为建议迁移**

```ini
建议迁移|prefix|D:\Projects\archive|迁移|归档项目，建议移到 NAS
```

**让系统目录里的某个缓存可以清**

```ini
可安全清理|contains|\windows\softwaredistribution\download\|删除|Windows 更新缓存|sys
```

**保护自己的重要目录**（写进 `[protect]`）

```ini
[protect]
C:\Users\Alex\Documents
C:\Users\Alex\OneDrive
D:\重要资料
```

### 8.6 改坏了怎么办

- 语法错误：重新加载时状态栏会提示，程序继续用**上一次成功的规则**
- 整个文件丢失：程序自动退回**内置兜底规则**，分类不会崩，只是不认你自己的定制
- 想回到出厂设置：从仓库里重新下载一份 `rules.ini` 覆盖

## 九、安全机制

这个工具的所有设计都围绕一个前提：**磁盘操作不可逆，误触的代价远大于省下的时间**。

| # | 机制 | 具体做法 |
|---|---|---|
| 1 | 扫描完全只读 | 扫描阶段不调用任何删除、移动、重命名 API |
| 2 | 删除只走回收站 | 用 Electron 的 `shell.trashItem`（= Windows 回收站），不是 `unlink` |
| 3 | 迁移先副本后原件 | 复制线程里**没有一行删除源文件的代码**；原件由主进程在拿到校验通过的结果后才动 |
| 4 | 绝不覆盖 | 目标存在同名文件一律放弃该项 |
| 5 | 只清自己的残骸 | 失败清理时同时校验「本次操作后新写」和「大小不对」，不碰别人的文件 |
| 6 | 保护名单 | `[protect]` 段 + 内置系统目录，界面禁用 + 执行前复核 |
| 7 | 不跟符号链接 | junction / symlink 直接跳过，避免目录回环 |
| 8 | 不结束进程 | 不会去关微信、Docker、浏览器来「解锁」文件 |

> 唯一使用 `unlink` 的地方：清理本次迁移写坏的半成品副本。用户文件一律不进这条路径。

## 十、故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 双击没反应 / 闪退 | 只拷了 exe，没带 `resources\` 和 dll | 整个文件夹一起拷 |
| 启动报错找不到 `rules.ini` | 规则文件没和 exe 放一起 | 从仓库拷一份过去；实在没有也会用内置兜底规则 |
| 扫描极慢 | 机械硬盘 / 网络盘 / 开了杀软实时扫描 | 关掉实时扫描再试，或只扫用户目录 |
| 点「移到回收站」没反应 | 有文件被占用（比如正在运行的安装包） | 结果里会标「文件被占用」，关掉对应程序再试 |
| 提示「权限不足」 | 文件属于 SYSTEM 或其他用户 | 跳过即可，这类文件本来也不该动 |
| 迁移提示「空间不足」 | 目标盘剩余 < 本次总量 | 换盘或分批 |
| 迁移后软件找不到文件 | 迁移不改配置 | 见 [6.5](#65-迁移之后要做的) |
| 分类明显不对 | 规则顺序 / 写法问题 | 看「判断依据」列，去 `rules.ini` 搜那句话 |
| 结果里「系统保护区」特别大 | 正常，`WinSxS` 动辄十几 GB | 不要动，这是系统组件仓库 |

## 十一、常见问题

**Q：会不会把我的文件删了？**
A：删除只走回收站，随时可还原。工具不会永久删除用户文件（唯一 `unlink` 用于清理自己写坏的副本）。

**Q：需要管理员权限吗？**
A：不需要。以普通用户运行即可扫描和整理用户区文件。提权只在清理系统目录时才需要，而系统目录本来就不建议动。

**Q：能定时自动清理吗？**
A：不能，也不打算做。这个工具的定位是「你看着办」，自动化清理磁盘是危险组合。

**Q：支持 ARM 版 Windows 吗？**
A：暂未提供 arm64 包。可以在 ARM 机器上按源码方式运行，或用 x64 版本（走兼容层，性能有折损）。

**Q：为什么不做重复文件检测？**
A：czkawka 已经做得很好，重复检测又需要另一套哈希索引。这个工具专注「体积分布 + 处置建议」。

**Q：扫描时 CPU 占用高吗？**
A：扫描跑在独立 Worker 线程，不阻塞界面。CPU 单核接近满载，这是遍历几十万文件的正常开销。
